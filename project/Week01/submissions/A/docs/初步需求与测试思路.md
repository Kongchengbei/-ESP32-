# 初步需求与测试思路

先把投喂系统要做的事讲清楚，再讨论程序怎么验证。现有方案中，HUSKYLENS负责识别猫类别，ESP32读取识别结果和食盆重量，再决定是否开门。称重测的是食盆中的粮，不是猫的重量。

从操作者的角度看，需要关注几个问题：什么时候允许投喂，盆里还有粮时怎么办，同一目标一直停在镜头前会不会反复出粮，以及出现异常时能不能停下来。data/requirements_baseline.csv先把这些问题记下来，后面结合调研和设备条件再补充具体标准。

第一周先整理测试方向：正常条件下能否进入投喂流程；不满足条件时是否拒绝开门；出现故障后是否停止；复位后是否需要重新布防。这里暂不展开毫秒边界和完整测试用例，也不要求运行驱动测试。

第二周和曾崇豪确认各项要求对应的程序位置，与刘营鑫商量哪些情况适合先仿真，再和杜若熙确认哪些必须在实物上测。测试用例和执行记录留到后续阶段逐步补充。

参考资料：00_开始阅读.md、02_驱动工程/CampusCatFeederESP32/README.md。这里记录的是根据已有方案整理的初步要求，还需要团队和实际使用场景确认。
